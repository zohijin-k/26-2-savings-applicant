# 재업로드 정책과 안내 문구 초안 — 승인 요청

## 선택 규칙
아래 10개 코드에 대해 finding.severity=FAIL인 경우만 재업로드 대상이다. 동일 코드라도 NEEDS_REVIEW이면 신청자에게 노출하거나 차단하지 않는다. 원래 severity 누락은 기존 규칙대로 FAIL로 해석하되, code 자체가 없으면 재업로드 대상으로 추론하지 않는다. 원문 message 문구나 문서의 전체 stage1_status로 대신 판단하지 않는다.

## 실제 사유 코드와 모달 안내
문구의 `{서류명}`, `{기준일}`, `{서류발급일}`, `{인정마지막날}`, `{고지월목록}`, `{빠진쪽}`, `{올린서류명}`은 서버가 보유한 공개 요건·신청자에게 공개 가능한 값만 사용한다. 내부 점수/판독 신뢰도/타인 성명은 채우지 않는다. 날짜는 기준일 당일을 포함한다.

구현 문구에서는 위 표의 마지막 설명 문장(추측 금지·개발 지침)은 민원인에게 노출하지 않고 개발 수용 기준으로 적용한다. 실제 발급처는 고정 기관 하나로 단정하지 않고 현재 체크리스트의 issuer/issuer_url을 사용한다.

## 명시적으로 제외할 가까운 코드
| 코드/상태 | 제외 이유 |
|---|---|
| DECLARED_DATE_MISMATCH | 신청자가 입력한 날짜와 판독 날짜의 차이이며, 발급일 인정 기간 위반 자체가 아님 |
| DECLARED_DATE_UNCERTAIN, LOW_OCR_CONFIDENCE, IDENTITY_UNCERTAIN | 판독 불확실; 모든 NEEDS_REVIEW 숨김 원칙 |
| PAGES_UNREADABLE | 쪽수 표시를 못 읽은 상태이며 빠진 쪽이 확정된 것이 아님 |
| PAGES_DUPLICATED | 구현상 전체 쪽은 다 있고 중복만 있는 별도 분기; 쪽 누락 한정 요청 밖 |
| DAILY_RECORDS_PARTIALLY_SELECTED | 사용자가 명시한 숨김 대상. 원래 FAIL 및 근로 UNDETERMINED는 그대로 저장 |
| UNKNOWN_DOCUMENT_TYPE | 종류 미확정이며 다른 종류라고 확정된 것이 아님 |
| MISSING_ADDRESS_HISTORY, NHIS_HISTORY_PERIOD_MISSING, MISSING_REQUIRED_FIELD, MISSING_SIGNATURE 등 | 요청한 재업로드 목록 밖. 입력 서식의 필수 동의·서명 검사는 별도 유지 |
| OVER_LIMIT, AGE_OUT_OF_RANGE, WORK_CONTINUITY_NOT_MET 등 | 자격·소득·연령·근로 내부 판단; 제출 허용 및 원판정 저장 |
| 동일 허용 코드의 NEEDS_REVIEW | 코드만으로 확정 FAIL로 승격하지 않음 |

## 발급처 링크 검증과 한계
- 정부24 주민등록표 등본(초본) 발급: https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=13100000015 (2026-11-13 공개 페이지 확인; 로그인 후 메뉴는 검증하지 않음)
- 국민건강보험공단 공식 홈페이지: https://www.nhis.or.kr/nhis/index.do 및 공식 민원업무 안내 https://www.nhis.or.kr/static/html/guide/sub1_02.html (보험료 납부확인서 발급 제공 확인)
- 초본 날짜 선택 요구와 심사 고지월은 저장소 체크리스트·원래 검증 코드의 요구사항이며 외부 기관 전체에 일반화한 법적 안내가 아니다. 검증되지 않은 클릭 순서/버튼 이름은 만들지 않는다.
