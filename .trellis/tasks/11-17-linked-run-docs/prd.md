# 담당자 화면과 연결 실행 안내

Source: 팀장 결정 2026-11-17 — 담당자 저장소 태스크 `11-17-unified-backend`의 D3. 이 저장소의 백엔드 코드는 그대로 두고 문서에만 연결 실행 안내를 더한다. 담당자 저장소의 PR #16은 2026-11-17에 병합됐다.

## Goal

이 저장소만 보는 사람도 두 가지를 알 수 있게 한다. 신청자 화면에서 낸 신청을 담당자 화면에서 보려면 무엇을 띄워야 하는지, 그리고 신청자 API를 고칠 때 무엇을 함께 고쳐야 하는지다.

## Background

- 담당자 저장소(`26-2-savings-officer`, `main` 3d1b801)의 백엔드가 신청자 API와 담당자 API를 함께 제공한다. 그 백엔드 하나에 두 프런트를 붙이면 한 DB로 이어진다. 두 프런트의 `/api` 프록시 기본값은 모두 `localhost:8000`이다.
- 이 저장소의 백엔드는 그대로 있고 단독 개발에 쓴다. 이 저장소의 백엔드를 띄우면 신청은 이 저장소의 `demo/demo.db`에 쌓이고 담당자 화면에는 보이지 않는다. 판정도 이 저장소의 코드로 된다(담당자 저장소의 판정 코드가 더 최신이다).
- 신청자 API 코드(`demo/backend/api/applications.py`, `documents.py`, `review.py`와 `common.py`의 신청자 응답 부분)가 두 저장소에 같은 내용으로 있다.

## Requirements

- **R1** `docs/DEVELOPMENT.md`에 "담당자 화면과 연결해서 실행" 절과 목차 항목을 더한다. 띄울 것 세 가지, 명령, 주의점을 적는다.
- **R2** `README.md`에 짧은 안내와 그 절로 가는 링크를 더한다.
- **R3** `.trellis/spec/backend/applicant-submission.md`에, 같은 신청자 API 코드가 담당자 저장소에도 있으며 한쪽을 고치면 다른 쪽에도 반영한다는 규칙을 더한다.

## Acceptance Criteria

- **AC1** 문서의 구성과 명령이 담당자 저장소 문서의 절차와 같다(백엔드 8000, 신청자 프런트 5173, 담당자 프런트 5174).
- **AC2** 바뀐 파일은 문서 3개와 이 태스크 폴더뿐이다. `demo`, `engine`, `engine_v2` 변경 0.

## Out of Scope

- 이 저장소의 백엔드·엔진·시험·프런트 변경.
- 담당자 저장소의 판정 코드를 이 저장소로 옮기는 일.
