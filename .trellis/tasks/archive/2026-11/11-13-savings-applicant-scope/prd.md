# 1단계: 화면 정리와 README

## 목표
두배적금 신청자가 앱을 열자마자 본인인증을 시작하며, 이 저장소에 다른 역할·사업 화면이 남지 않는다.

## 요구사항
- S1-1: 루트·첫 진입 및 홈 버튼은 두배적금 본인인증으로 간다. 네트워크 재시도·React effect 재실행으로 중복 초안을 만들지 않는다. 기존 두배적금 진행 세션은 새로고침 시 복원한다.
- S1-2: 담당자 pages, 역할 탭/라우트, 목업, 담당자 전용 API 클라이언트·기준 편집 UI 제거. 취업패키지 선택/지원항목/서식 및 업로드의 전용 UI·분기·문구 제거. 공유 PDF·모달·서명 컴포넌트는 두배적금 사용 여부로 보존한다.
- S1-3: 백엔드 담당자/취업 API·모델·저장·공유 템플릿은 유지. 프런트 호출이 사라진 목록을 보고한다.
- S1-4: 루트 README를 두배적금 신청자 저장소 설명으로 다시 작성. 안내 저장소 `https://github.com/zohijin-k/26-2-capstone`과 savings-officer/youth-applicant/youth-officer 링크 및 정확한 두 실행 명령 포함. `서류 업로드만 시험할 때 (개발용)` 절의 명령/같은 탭 주의/정리 절차를 유지한다. 루트 README의 담당자·취업 기능 설명은 제거하되 관련 저장소 링크명은 요구대로 둔다.
- S1-5: docs/DEVELOPMENT.md, demo/README.md는 삭제 화면·저장소 정체성·잘못된 시험 수 등 사실만 최소 정정. 문서 전체 재편이나 다른 문서 확장 편집은 하지 않는다.

## 수용 기준
- / 및 옛 역할/사업 선택 URL에서 두배적금 본인인증이 나오며 다른 역할/사업을 고를 수 없다.
- 두배적금 인증->서식->업로드->최종 확인->제출 및 마이페이지가 기존 정책대로 동작한다. 4단계 제거는 2단계 소유다.
- 타입 검사·lint·build와 전체 엔진/백엔드/18개 시나리오 통과. 시험 삭제·기대값 변경 예정 0.
- 기존 백엔드 파일과 엔진 파일은 이 단계에서 수정하지 않는다.
- 공통 기준·제외 범위·승인 절차는 상위 PRD를 따른다.
