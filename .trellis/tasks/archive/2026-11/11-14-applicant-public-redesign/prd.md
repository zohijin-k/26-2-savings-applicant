# 신청자 화면 공공서비스 리디자인 및 OCR 체감 대기시간 개선

## Goal

민원인이 쓰는 두배적금 신청 3단계 화면(본인인증 → 서식 작성 → 서류 업로드·제출)과
완료·마이페이지 화면을 실제 공공기관 서비스로 내놓을 수 있는 수준으로 다시 디자인한다.
기준은 "민원이 나오지 않는 화면"이다: 무엇을 해야 하는지, 지금 무슨 일이 일어나는지,
잘못됐을 때 어떻게 고치는지를 화면이 스스로 설명해야 한다. 백엔드는 바꾸지 않고
프런트엔드만으로 OCR 판독 중 체감 대기시간을 줄인다.

## Background

- 사용자 결정 (2026-11-14):
  - 디자인 기준은 저장소 루트 `jb.png`(전북특별자치도 · 2026 전북청년 함께 두배적금 배너)다.
  - OCR 실제 속도 단축은 OCR·rule-base 작업 영역이므로 하지 않는다. 백엔드 코드는 수정하지 않는다.
  - "구현 완료 후에 알려주세요" — 계획 검토로 멈추지 않고 구현·검증까지 진행한 뒤 보고한다.
- `jb.png` 색: 전북 블루 `#084090`, 남색 `#182880`, 청록 `#00A8D0`, 자홍 `#E00078`,
  배경 연녹 `#F3F8EC` → 크림 `#FCF5E5`.
- 현황 감사는 `research/audit-*.md` 8개에 있다. 핵심 사실:
  - 색 119종, 글자 크기 20종(대부분 11–13px, 본문 14px), 모서리 14종, 버튼 높이 7종,
    포커스 표시 5종, 주요 버튼 색 2종(남색·파랑)이 한 화면에 섞여 있다. 아이콘은 유니코드 글리프다.
  - 화면 틀에 기관 표시·문의처·바닥글·건너뛰기 링크·`<main>`이 없고, 제목이 두 번 겹쳐 나온다.
  - 서류 한 건을 올리면 페이지 전체가 `inert`로 잠기고, 문구는 화면 밖 맨 아래 한 줄뿐이다.
    다시 올릴 때는 진행 표시가 아예 없다. 응답으로 받은 결과를 버리고 조회 2건을 더 기다린다.
  - 로컬 측정: 텍스트 PDF 0.14초, 사진(JPG) 약 3초, 스캔 PDF 쪽당 약 4초(3쪽 12초).
    전북AI 연동 시 최악 60초 이상. 백엔드는 OCR 동안 다른 요청에 응답하지 못한다.
  - 기계 판정으로 반려되면 제출이 막히는데 화면에 문의처가 없다. 제출 전 확인 단계도 없다.
  - 기술 오류 문구(`GET /api/... 실패 (500)`, `Failed to fetch`)가 그대로 노출된다.
  - 모바일에서 마이페이지(940px 고정)와 서류 카드 머리글이 깨진다.

## Requirements

### R1. 디자인 기반 (전 화면 공통)

- R1.1 `jb.png`에서 뽑은 전북 블루 계열을 주 색으로 하는 단일 토큰 체계(색·글자·간격·모서리·그림자·
  포커스)를 두고, 신청자 화면의 모든 CSS가 그 토큰만 쓴다. 청록·자홍은 장식 강조에만 쓴다.
- R1.2 본문 16px 이상, 보조 글자 13px 이상. 반 픽셀 크기를 없앤다.
- R1.3 버튼은 주(채움)·보조(테두리)·조용한(글자) 세 위계와 세 높이(56·48·40px)만 쓴다.
  한 화면의 주 버튼은 한 종류 색이다. 입력창 높이는 48px이다.
- R1.4 포커스 표시는 한 가지 규칙으로 모든 조작 요소에 보인다(대비 3:1 이상).
- R1.5 글자·아이콘 대비는 4.5:1 이상(큰 글자 3:1), 상태는 색만으로 구분하지 않는다.
- R1.6 아이콘은 유니코드 글리프 대신 인라인 SVG 한 세트를 쓴다.
- R1.7 UI 글꼴은 자체 호스팅 Pretendard GOV(OFL)로 통일한다. 외부 CDN 요청은 만들지 않는다.
  내려받을 수 없으면 시스템 글꼴 스택으로 대체하고 그 사실을 보고한다. 서식 재현용 Noto 글꼴과
  경로는 그대로 둔다.
- R1.8 `prefers-reduced-motion`을 모든 애니메이션에 적용한다.

### R2. 화면 틀

- R2.1 상단에 `jb.png` 배너를 기관·사업 표시로 쓰고, 건너뛰기 링크·`<header>`·`<main>`·`<footer>`를 둔다.
- R2.2 바닥글에 사업명, 문의처(`call_center`, `tel:` 링크), 안내 문구를 둔다. 문의처는 모든 단계에서 같은 자리에 보인다.
- R2.3 단계마다 문서 제목(`document.title`)이 달라지고, 단계가 바뀌면 포커스가 새 단계 제목으로 간다.
- R2.4 로고(처음으로)를 누르면 새 신청이 시작된다는 것을 확인 대화상자로 먼저 알린다(진행 중인 신청이 있을 때).
- R2.5 작성 중인 신청은 같은 탭에서만 이어 쓸 수 있다는 사실을 안내하고, 본인인증 뒤 제출 전까지
  탭을 닫거나 새로 고치려 하면 브라우저 이탈 확인을 띄운다.
- R2.6 기술 오류 문구를 민원인용 문장으로 바꾼다. 서버가 준 안내(`detail`)가 있으면 그것을 보여 준다.
- R2.7 단계 표시는 이어진 선과 원형 표식을 유지하되, 완료·현재·예정이 아이콘과 글자로 분명히 구분된다.

### R3. 1단계 본인인증

- R3.1 시작 전에 절차(3단계)·준비물·"같은 탭에서만 이어 쓰기"를 알려 준다. 근거 없는 소요 시간 수치는 쓰지 않는다.
- R3.2 각 입력에 레이블·도움말·오류 문구가 연결된다. 오류는 어디가 왜 틀렸고 어떻게 고치는지 말한다.
- R3.3 주 버튼을 말없이 꺼 두지 않는다. 누르면 빠진 항목을 알려 주고 첫 항목으로 포커스를 옮긴다.
- R3.4 생년월일은 실재하는 날짜인지 화면에서 확인한다. 범위를 넘는 입력을 말없이 버리지 않는다.
- R3.5 본인인증 정보는 뒤에 고칠 수 없으므로, 보내기 전에 입력값을 다시 보여 주고 확인받는다.
- R3.6 `verifyIdentity` 요청 본문과 이후 저장 순서는 바꾸지 않는다. "데모 화면" 안내 문구의 사실 관계는 유지한다.

### R4. 2단계 서식 작성 (원본 PDF 주변만)

- R4.1 서식 목록·문서 머리·도구줄·버튼을 R1 토큰으로 다시 입힌다. PDF 위 입력 좌표·배율·글꼴은 건드리지 않는다.
- R4.2 서식별 상태(미작성·작성 중·작성 완료)가 아이콘과 글자로 구분되고, 남은 항목 수가 읽을 수 있는 크기로 보인다.
- R4.3 "서류 업로드로"를 말없이 꺼 두지 않는다. 누르면 덜 쓴 서식과 남은 항목 수를 알려 주고 그 서식으로 갈 수 있다. 통과 조건 자체는 그대로다.
- R4.4 필수 빈칸은 처음에는 차분한 "작성할 칸" 표시로, 저장·다음 단계를 시도한 뒤에만 오류 색으로 보인다.
- R4.5 서식 쪽 이미지가 오기 전에는 자리 표시를 보여 주고, 서식을 바꿀 때 누른 항목에 진행 표시가 뜬다.
- R4.6 저장 상태(저장 중·저장됨·저장 실패)가 문서 머리에서 항상 읽힌다. 별도 안내 줄을 상시 예약하지는 않는다.
- R4.7 내려받기 메뉴는 Esc·바깥 클릭으로 닫힌다. 브라우저 기본 `confirm` 4곳은 화면 대화상자로 바꾼다.
- R4.8 저장되지 않은 변경이 있거나 저장 중일 때 탭을 떠나려 하면 이탈 확인을 띄운다.

### R5. 3단계 서류 업로드 — 체감 대기시간 (프런트엔드만)

- R5.1 파일을 고른 즉시(100ms 안) 그 칸에 파일 이름·크기·미리보기와 진행 상태가 보인다. 카드가 접히거나 비는 구간이 없다.
- R5.2 서버로 보내는 동안 실제 전송률(%)을 보여 준다.
- R5.3 전송 뒤 판독·확인 구간은 "서류를 읽고 확인하고 있습니다" 문구와 경과 시간으로 보여 준다.
  가짜 퍼센트와 지어낸 세부 단계는 쓰지 않는다. 예상 시간은 파일 종류·쪽수(텍스트 PDF 여부 포함)와
  이번 접속에서 실제로 걸린 시간으로 추정하고 "예상"이라고 밝힌다.
  예상을 크게 넘기거나 10초를 넘기면 "평소보다 오래 걸리고 있습니다. 창을 닫지 말고 기다려 주세요"로 바뀐다.
- R5.4 한 서류를 읽는 동안에도 페이지가 잠기지 않는다. 다른 서류의 발급일을 적고 파일을 골라 둘 수 있고,
  고른 파일은 "대기 중"으로 줄을 서서 차례로 올라간다. 대기 중인 파일은 취소할 수 있다.
  서버 요청은 한 번에 하나만 보낸다(백엔드 동시성 제약).
- R5.5 결과는 업로드 응답으로 바로 그린다. 목록·제출 준비 재조회는 뒤에서 한다.
- R5.6 다시 올릴 때도 같은 진행 표시가 나온다. 이전 반려 표시가 판독 내내 남아 있지 않는다.
- R5.7 올리기 전에 화면에서 걸러 낸다: 지원하지 않는 형식(HEIC 포함, 바꾸는 방법 안내), 빈 파일, 암호 걸린 PDF.
  서버가 받아 줄 파일을 화면이 막지는 않는다.
- R5.8 텍스트 PDF가 가장 빠르고 정확하다는 사실을 올리기 전에 안내한다(발급처 원본 PDF 권장).
- R5.9 적어 둔 발급일은 새로 고쳐도 남고, 올리는 중에 탭을 떠나려 하면 이탈 확인을 띄운다.
- R5.10 진행·완료·반려는 스크린리더에 한 번씩 알린다(칸별 상시 live 영역).

### R6. 3단계 서류 업로드 — 민원 예방

- R6.1 받는 형식·권장 형식·촬영 요령을 올리기 전에 보여 준다. 끌어다 놓기와 버튼을 함께 제공한다.
- R6.2 반려 사유와 해결 방법을 그 칸 안에서 바로 읽을 수 있다(승인된 고정 안내 문구 그대로).
  "자동 확인 결과"임을 밝히고, 올바른 서류인데도 반복되면 문의처로 연락하라고 안내한다.
- R6.3 재업로드 안내 대화상자는 새 반려가 생겼을 때 한 번만 저절로 열리고, 방문할 때마다 다시 열리지 않는다. 언제든 다시 열 수 있다.
- R6.4 올리기 실패(통신·서버 오류)는 그 칸에 민원인용 문장으로 나오고, 같은 파일로 다시 시도할 수 있다.
- R6.5 진행 수치는 "업로드 완료"만 센다. 다시 올려야 하는 서류는 따로 센다.
- R6.6 날짜는 `2026. 3. 3.` 형식으로 보여 준다.
- R6.7 제출은 되돌릴 수 없으므로, 제출 전에 요약과 함께 확인 대화상자를 거친다.
- R6.8 접수 완료 화면은 접수증 형태다: 제목, 신청번호, 접수 일시, 다음 절차, 문의처, 인쇄.
  새로 고쳐도 같은 내용이 보인다(서버가 주지 않는 항목은 지어내지 않고 생략한다).
- R6.9 근로유형 선택은 누른 즉시 반영돼 보인다.

### R7. 마이페이지

- R7.1 좁은 화면과 200% 확대에서 가로 스크롤 없이 읽힌다.
- R7.2 진행 단계의 현재 위치가 색 외 수단으로도 구분되고, 문의처는 `tel:` 링크다. 불러오기 실패 시 다시 시도할 수 있다.
- R7.3 심사 점수·내부 판정은 계속 보이지 않는다.

### R8. 유지해야 하는 계약

- R8.1 백엔드(`demo/backend`, `engine*`) 파일을 수정하지 않는다. API 요청·응답 형태를 바꾸지 않는다.
- R8.2 URL 체계(`/apply/{identity|forms|upload|complete|mypage}`, `final` 별칭), sessionStorage 키
  `applicant.activeApplicationId`, URL에 신청 ID·개인정보 없음.
- R8.3 원본 PDF 충실도: 배경·마스크·입력·쪽 높이를 한 배율로 맞추는 렌더러, 좌표, 서식 글꼴, 공개 서식 번호·순서.
- R8.4 저장 전이: 서식 전환·미리보기 전 `onFlush`, `finally`에서 이동 금지, 서명 대화상자의 Esc·스크롤 잠금·포커스 가두기·복귀.
- R8.5 신청자 상태 표시는 `업로드 완료` / `다시 올려 주세요` 두 가지, 반려 사유는 10개 코드의 고정 안내 문구만.
  원시 판정·신뢰도·점수·타인 정보는 노출하지 않는다.
- R8.6 파일 이름 `PdfFormsWorkspace.tsx`, `pdf-forms-workspace.css`, `DocumentUpload.tsx`를 유지하고,
  이 세 파일 밖의 `demo/` 아래 `.ts/.tsx/.css`에는 `download`·`attachment` 문자열을 넣지 않는다(P4 시나리오 검사).
- R8.7 Noto 서식 글꼴 파일 경로와 `@font-face`(`font-display: block`)를 유지한다.
- R8.8 테스트·도구가 쓰는 DOM id(`slot-*`, `upload-*`, `work-context`, `reupload-guidance-trigger`,
  `submission-heading`, `reupload-*`, `pdf-form-panel`, `pdf-form-panel-title`, `form-signature-file`, `identity-sign-file`)를 유지한다.

## Acceptance Criteria

- [ ] AC1 (R1) 신청자 화면 CSS에서 토큰 밖 색 리터럴은 PDF 시트 영역(`.pdf-form__*`, `form-sheet.css`)과 토큰 정의 파일에만 남는다.
- [ ] AC2 (R1) 1440×900 캡처에서 모든 화면의 주 버튼 색·모서리가 같고 높이는 세 크기(56·48·40px) 중 하나이며
  단계 진행 버튼(본인인증·서류 업로드로·신청 제출)은 모두 56px이다. 본문 글자가 16px 이상이다.

## Out of Scope

- 백엔드·OCR 엔진·판정 규칙 변경, 비동기 작업 API, 진행 단계 조회 API.
- 실제 본인인증(휴대폰·간편인증) 연동과 "데모 화면" 정책 문구의 삭제 여부 결정.
- 2단계 PDF 확대 기능, 좌표·서식 템플릿 변경, 모바일에서의 서식 작성 재설계.
- 여러 서류를 한 PDF로 올리는 병합 업로드 UI(현재도 진입점이 없음).
- 대한민국 공식 전자정부 누리집 배너(운영기관 확인이 필요한 표시).
- 운영 배포 설정(SPA 경로 재작성 등).

## Deferred (보고에 남길 것)

- 백엔드가 OCR 동안 이벤트 루프를 막아 다른 요청이 멈춘다. 프런트는 대기열로 우회만 한다.
- 서버에 파일 크기·쪽수 상한이 없다. 화면은 큰 파일에 시간 안내만 한다.
- 제출 후에도 업로드 API가 열려 있다.
- `jb.png`는 297×100 해상도다. 고해상도 원본이 있으면 교체가 필요하다.
