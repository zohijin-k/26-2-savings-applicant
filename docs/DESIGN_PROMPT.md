# 청년정책 신청 화면 디자인 프롬프트

전북청년 함께 두배적금 신청자 화면에 적용한 디자인을 다른 청년정책 신청 화면에 그대로 옮기기 위한 프롬프트입니다.
아래 "채울 값"만 바꿔서 `---` 아래 전체를 AI 코딩 도구에 붙여 넣으면 됩니다.

기준 구현: <https://github.com/zohijin-k/26-2-savings-applicant> 의 `demo/frontend/src`
(`styles/tokens.css`, `styles/base.css`, `styles/components.css`, `components/`, `pages/applicant/`).

## 채울 값

| 항목 | 값 |
|---|---|
| 사업명 | 예: 전북청년 취업지원패키지 |
| 운영기관 | 예: 전북특별자치도 |
| 로고 파일 | 저장소 안 경로. 가로형 1개(필수), 정사각 심볼 1개(있으면) |
| 문의 전화 | 예: 1660-2040 (없으면 "없음") |
| 신청 단계 | 예: 본인인증 → 서식 작성 → 서류 업로드 및 제출 |
| 대상 화면 | 고칠 화면·폴더 경로 |
| 건드리면 안 되는 것 | 예: 백엔드, API 형태, 원본 서식 좌표 |

---

당신은 공공기관 민원 서비스의 프런트엔드를 다시 디자인합니다. 대상은 청년정책 「{사업명}」({운영기관}) 신청자 화면이고,
쓰는 사람은 일반 민원인입니다. 목표는 **민원이 나오지 않는 화면**입니다. 화면이 스스로 "무엇을 해야 하는지,
지금 무슨 일이 일어나는지, 잘못됐을 때 어떻게 고치는지"를 설명해야 합니다. 차분하고 일관되게 만드세요.
꾸밈보다 정돈이 우선입니다.

- 로고: `{로고 파일}` / 문의 전화: `{문의 전화}` / 단계: `{신청 단계}`
- 고칠 범위: `{대상 화면}` / 건드리지 않는 것: `{건드리면 안 되는 것}`

기능과 데이터 흐름은 바꾸지 않습니다. API 요청·응답, URL 체계, 저장 순서, 통과 조건은 그대로 두고 보이는 방식과
안내만 바꿉니다. 새 npm 의존성과 외부 CDN 요청(글꼴·아이콘 포함)은 추가하지 않습니다.

## 1. 브랜드 색은 로고에서 뽑는다

1. 로고 이미지를 직접 열어 보고, 픽셀을 표본 추출해 잉크 색(글자·심볼)과 배경색을 구합니다. 눈대중으로 정하지 않습니다.
2. 가장 많이 쓰인 진한 색을 **주 색(primary)** 으로 삼습니다. 흰 배경 대비가 7:1 이상이어야 합니다.
   모자라면 같은 색상(hue)에서 명도만 낮춥니다.
3. 주 색에서 9단계 척도를 만듭니다: `5`(아주 옅은 배경) · `10` · `20` · `30` · `40` · `50`(포커스 고리, 대비 4.5:1 이상) ·
   `60`(주 색) · `70`(hover) · `80`(pressed).
4. 로고의 나머지 색(보조 색 1~2개)은 **장식 전용**입니다. 상단 강조 띠처럼 정보가 없는 곳에만 쓰고,
   글자색·상태 색·버튼 색으로 쓰지 않습니다. 빨강·자홍 계열은 오류로 읽히므로 특히 그렇습니다.
5. 회색과 상태 색(오류·주의·성공·안내)은 아래 값을 그대로 씁니다. 사업마다 바꾸지 않습니다.
6. 쓰는 모든 글자/배경 조합의 대비를 계산해 4.5:1 이상(큰 글자 3:1)인지 확인하고 결과를 보고합니다.

## 3. 기본 규칙

- **글꼴**: Pretendard GOV(OFL 1.1) 400·500·700 woff2를 저장소에 넣어 `font-display: swap`으로 씁니다
  (npm `pretendard-gov`의 subset woff2). 라이선스 파일을 함께 두고 제3자 고지에 적습니다. 받을 수 없으면 위 글꼴 순서로 대체합니다.
- **글자**: 본문 16px, 줄 간격 1.55, `word-break: keep-all`. 제목 h1 24 / h2 22 / h3 19 / h4 17px, 모두 700.
  보조 글자 15px, 가장 작은 글자 13px. 반 픽셀 크기와 13px 미만은 쓰지 않습니다.
- **모서리**: 4 / 6 / 8 / 12px와 pill만. 버튼·입력 8px, 작은 버튼 6px, 카드·대화상자 12px, 배지 4px.
- **반응형**: 분기점은 `max-width: 900px`(열 쌓기)와 `600px`(폰) 두 개뿐입니다. 390px에서 가로 스크롤·겹침·
  글자 단위 줄바꿈이 없어야 합니다.
- **포커스**: 전역 규칙 하나만 둡니다. `:focus-visible { outline: 3px solid var(--color-focus); outline-offset: 2px; }`
  컴포넌트마다 따로 만들지 않습니다.
- **움직임**: `prefers-reduced-motion: reduce`에서 모든 애니메이션·전환을 끕니다.
- **아이콘**: 24 격자, 선 굵기 1.75, `currentColor`인 인라인 SVG 한 세트. 유니코드 기호(✓ ✕ ↻ ⓘ ◀ ▶ ↗)를 아이콘으로 쓰지 않습니다.
- **상태 표시**: 색만으로 구분하지 않습니다. 항상 아이콘이나 글자를 함께 둡니다.

## 5. 화면 틀

```
[건너뛰기 링크 "본문으로 건너뛰기"]
<header>  흰 배경, 아래 1px 테두리, 맨 위 4px 강조 띠
          왼쪽: 로고(처음으로 버튼) / 오른쪽: 신청번호(레이블 13 + 값 15/700) + "마이페이지"(작은 보조 버튼)
<main id="main">
  머리 띠(흰 배경, 화면 폭 전체): h1 "{사업명} 신청" → 그 아래 단계 표시
  본문: 폭 880px 가운데 정렬 (문서 작업 화면처럼 넓어야 하면 1200px)
<footer>  흰 배경, 위 1px 테두리: 「{사업명}」 신청 · {운영기관} / 문의 {문의 전화}(tel: 링크)
```

- **로고**: 높이 48px(폰 40px). 배경이 투명한 로고는 그대로 놓습니다. 자체 배경이 있는 배너형 로고는
  모서리 8px, gray-20 1px 테두리의 칩으로 감싸 의도된 모양으로 보이게 합니다. `alt`에는 기관명과 사업명을 적습니다.
  로고를 늘리거나 색을 바꾸거나 글자로 다시 그리지 않습니다.
- **강조 띠**: 로고 색 비율로 만든 가로 그라데이션(주 색 약 62% · 보조 색 22% · 16%). 로고가 한 색이면 주 색 단색.
- **문의처**: 모든 단계에서 바닥글 같은 자리에 보입니다. 문의 전화가 없으면 그 줄을 생략합니다(지어내지 않습니다).
- **단계마다** `document.title`이 다르고(`{단계명} | {사업명} 신청`), 단계가 바뀌면 화면을 맨 위로 올리고 새 단계 제목으로 포커스를 옮깁니다.
- 주소·운영 시간·정책 문구처럼 확인되지 않은 정보는 넣지 않습니다.

## 6. 신청 흐름 패턴

- **단계 표시**: `<ol>`, 2px 선으로 이어진 32px 원형 표식(폰 24px). 완료 = 주 색 채움 + 흰 체크, 현재 = 주 색 고리 + 점,
  예정 = 회색 고리 + 숫자. 아래에 `N단계 · 상태`(13px)와 단계 이름(16/700). 현재 단계는 `aria-current="step"`.
  이동할 수 없는 단계는 버튼이 아니라 글자로 둡니다. 모든 단계에서 같은 자리에 둡니다.
- **시작 안내**: 첫 단계 맨 위에 info 안내 상자로 절차, 준비물, 주의할 점을 사실만 적습니다. 소요 시간 같은 근거 없는 수치는 쓰지 않습니다.
- **입력 검증**: 한 번 손댄 칸은 벗어날 때 확인하고, 제출을 누르면 전체를 확인합니다. 실패하면 양식 위에
  오류 요약(danger 안내 상자, `role="alert"`, 각 항목이 해당 칸으로 가는 링크)을 띄우고 첫 오류 칸으로 포커스를 옮깁니다.
  오류 문구는 "무엇이 왜 틀렸고 어떻게 고치는지"를 말합니다. 범위를 넘는 입력을 말없이 버리지 않습니다.
- **되돌릴 수 없는 동작**(본인 정보 확정, 최종 제출, 새로 시작, 내용 지우기)은 요약을 보여 주는 확인 대화상자를 거칩니다.
- **작업 중 이탈**: 저장되지 않은 내용이나 진행 중인 요청이 있으면 `beforeunload`로 이탈을 확인합니다.
- **하단 버튼 줄**: 왼쪽에 보조·조용한 버튼, 오른쪽에 주 버튼(56px). 폰에서는 주 버튼이 위로 오게 세로로 쌓고 폭을 채웁니다.
- **덜 채운 채 다음 단계**: 버튼을 끄지 않고, 누르면 warning 안내 상자로 남은 항목과 개수를 보여 주며 각 항목이 그 자리로 이동시킵니다.
- **필수 빈칸**: 처음에는 차분한 브랜드 색 테두리("작성할 칸")로, 저장·다음 단계를 시도한 뒤에만 오류 색으로 바꿉니다.
- **저장 상태**: `저장 중…` / `저장했습니다` / `저장하지 못했습니다`를 작업 영역 머리에 항상 보이게 둡니다.
- **접수 완료**: 접수증 카드. 옅은 그라데이션 머리(성공 아이콘 + "신청이 접수되었습니다"), 신청번호(19/700)·접수 일시·사업명·문의,
  다음 절차, 인쇄 버튼. 새로 고쳐도 같은 내용이 보여야 하고, 서버가 주지 않는 항목은 생략합니다.
- **마이페이지**: 진행 단계(같은 표식 언어, 현재 단계에 `진행 중` 글자), 제출 서류 표(폰에서는 줄마다 카드로 쌓음), 이력. 내부 점수·판정은 보이지 않습니다.

## 7. 기다리는 화면 (파일 올리기, 자동 확인처럼 1초 넘게 걸리는 일)

체감 시간을 줄이는 규칙입니다. 서버를 고치지 않고 화면에서만 합니다.

1. **즉시 반응**: 파일을 고르면 0.1초 안에 그 자리에 파일 이름·크기·미리보기와 진행 상태를 보여 줍니다. 화면이 비거나 접히는 구간을 만들지 않습니다.
2. **실제 수치만**: 보내는 동안은 실제 전송률(%)을 보여 줍니다. 서버가 처리하는 동안은 길이를 모르므로 움직이는 막대 +
   "서류를 읽고 확인하고 있습니다." + 경과 시간 + `예상 약 n초`를 보여 줍니다. 가짜 퍼센트와 지어낸 세부 단계는 쓰지 않습니다.
   예상 시간은 파일 종류·쪽수와 이번 접속에서 실제로 걸린 시간으로 추정합니다.
3. **오래 걸릴 때**: 예상의 1.5배나 10초를 넘기면 "평소보다 오래 걸리고 있습니다. 창을 닫지 말고 기다려 주세요."로 바꿉니다.
4. **페이지를 잠그지 않습니다**: 기다리는 동안 다른 칸을 채우고 다음 파일을 골라 둘 수 있게 합니다. 고른 파일은
   "대기 중"으로 줄을 세워 한 번에 한 건씩 보내고, 대기 중인 건은 취소할 수 있습니다.
5. **결과는 응답으로 바로** 그립니다. 목록 재조회는 뒤에서 합니다.
6. **보내기 전에 걸러 냅니다**: 지원하지 않는 형식(HEIC 포함), 빈 파일, 암호 걸린 PDF는 요청 없이 그 자리에서
   고치는 방법과 함께 안내합니다. 서버가 받아 줄 파일을 화면이 막지는 않습니다.
7. **빠른 길을 미리 알려 줍니다**: 받는 형식, 권장 형식, 촬영 요령을 올리기 전에 보여 줍니다.
8. **실패는 그 자리에**: 오류와 "같은 파일로 다시 시도"를 해당 칸 안에 둡니다. 자동 판정으로 반려됐을 때는
   사유·해결 방법과 함께 "자동 확인 결과입니다. … {문의 전화}로 문의해 주세요."를 붙입니다.
9. **알림**: 시작·완료·실패를 칸마다 항상 붙어 있는 `aria-live="polite"` 영역으로 한 번씩 알립니다.

## 8. 문구

- 합쇼체로 통일합니다("~합니다", "~해 주세요", "~하시겠습니까?"). 해요체를 섞지 않습니다.
- 기술 문구(`GET /api/…`, `Failed to fetch`, 상태 코드)를 화면에 내지 않습니다. 서버가 준 안내 문장이 있으면 그것을,
  없으면 "인터넷 연결을 확인한 뒤 다시 시도해 주세요." / "일시적인 문제로 처리하지 못했습니다. 잠시 후 다시 시도해 주세요."를 씁니다.
- 민원인 탓으로 읽히는 표현을 피하고, 자동 판정은 자동 판정이라고 밝힙니다.
- 날짜는 `2026. 3. 3.`, 일시는 `2026. 11. 14. 오후 5:20`, 전화는 `tel:` 링크로 씁니다.
- 버튼은 동사로 씁니다(파일 선택, 다시 올리기, 제출하기). "확인"만 있는 버튼을 피합니다.
- 이미 승인된 고정 문구(법정 안내, 사유별 안내문)는 어투를 맞춘다는 이유로 고치지 않습니다.

## 9. 접근성 점검

건너뛰기 링크 · `header`/`main`/`footer` · 제목 순서(h1→h2→h3) · 모든 입력의 레이블과 `aria-describedby` 연결 ·
키보드만으로 전 과정 완료 · 포커스가 항상 보임 · 조작 대상 40px 이상 · 대비 4.5:1 · 색 외 수단으로 상태 구분 ·
대화상자 포커스 가두기와 복귀 · 400% 확대/320px에서 내용 손실 없음 · 서명·끌어다 놓기에는 버튼 대안 제공.

## 10. 하지 말 것

- 토큰 밖 색·글자 크기·모서리 값 쓰기, 화면마다 다른 버튼 높이·색 만들기.
- 주 버튼을 말없이 비활성으로 두기, 처음 연 화면을 오류 색으로 채우기.
- 처리 중 페이지 전체 잠그기, 가짜 진행률, 근거 없는 소요 시간.
- 브라우저 기본 `confirm`/`alert`, 유니코드 기호 아이콘, 알약 배지, 왼쪽 색 띠 카드, 상자 속 상자.
- 로고 변형, 보조 색을 글자나 상태 색으로 쓰기.
- 확인되지 않은 기관 정보·정책 문구·"대한민국 공식 전자정부 누리집" 배너 넣기.
- 기능·API·URL·저장 순서·통과 조건 바꾸기.

## 11. 작업 순서와 검증

1. 지금 화면을 1440×900과 390×844로 캡처해 문제를 적습니다. 색·글자 크기·버튼 높이가 몇 종류인지 셉니다.
2. **기반 먼저**: 로고 색 추출 → `tokens.css` → 기본 규칙 → 컴포넌트 → 화면 틀. 여기까지 끝나면 모든 화면이 여전히 동작해야 합니다.
3. **화면별 적용**: 화면 CSS를 덧칠하지 말고 토큰으로 새로 씁니다. 쓰이지 않는 규칙은 지웁니다.
4. **검증**: lint·타입 검사·기존 시험이 모두 통과해야 하고, 새로 만든 순수 로직에는 단위 시험을 붙입니다.
   각 화면과 상태(빈 양식, 오류, 진행 중, 완료, 실패)를 다시 캡처해 직접 보고 고칩니다. 느린 응답은 응답을 인위로
   늦춰서 확인합니다.
5. **보고**: 바꾼 파일, 대비 계산 결과, 확인하지 못한 것(스크린리더, 다른 브라우저 등), 기존 규칙에서 일부러 바꾼 점을 적습니다.
